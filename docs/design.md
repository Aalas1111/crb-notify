# 设计：一个只做「收 + 判 + 发」的接收器

## 0. 为什么是**接收器**而不是 agent

这个项目是从 `crb-agent` 拆出来的。那一版想做一个「服务器替你调学校系统」的
agent（扫码登录、查空闲教室、提交申请、查审批结果），但**核心前提被实测推翻了**：

> 服务器（机房 IP）调不动办事大厅的接口。而且**换出口也没用** ——
> 用 SSH 隧道把服务器出口换成校园网（确认是同一个 IP）仍然 403；
> 同一份登录态、同一个出口 IP、同一组 header，**从本机发出 200、从服务器发出 403**。

七项候选都试过（出口 IP / cookie 完整性 / UA / TLS 版本 / 浏览器 TLS 指纹 /
HTTP 客户端 / cookie 过期），**确切机制没定位**，但结论可靠：请求必须从那台
能过的机器发出。那条路走不通，于是 `crb-agent` 归档，**只有「判定 + 出通知」这一半
是成立的**，它成了这个项目。

「读申请列表」交给**浏览器插件**（同学的活动工作台）—— 它跑在用户自己的浏览器里，
出口和「是不是本机」天然满足。

```
浏览器插件（校园网 / 用户浏览器）
    │ POST /intake/records        ← 契约见 intake-contract.md
    ▼
crb-notify（8788）
    │ classify()：可测量的判定（查表 + 关键词）
    ▼
账本（只追加，按 SQBH）── 内容不是纯函数，得留痕
    │ build_notifications()：文档是账本的**纯函数**
    ▼
notifications.json（对外）  unmatched.json（认不出的，等人看）
    │
    ├─▶ QQ：写 yqa 的 outbox/notify/pending/  ← 桥取件；**不改桥的代码**
    └─▶ 语雀《审批结果》：调 yqa refresh-approval
```

## 1. 判定：可测量的事实，不是判断

`classify()` 只做查表与正则，**没有 LLM**。规则照抄同学那个插件在生产里跑着的
`recordLifecycle()`（中文关键词比学校内部的码表稳 —— 码表会变）：

| 顺序 | 规则 | 结果 |
|---|---|---|
| 1 | 含「暂存/草稿」或 `SHZT=00` | 草稿（不通知） |
| 2 | 含「撤回\|不通过\|驳回\|拒绝\|退回\|取消」 | **已退回** |
| 3 | 含「通过\|批准\|同意」 | **已通过**（但必须能读到教室，见下） |
| 4 | 含「待\|审核\|提交\|完成」 | 还在流程（不通知） |
| 5 | 其它 | **认不出** → `unmatched.json` 等人看 |

**顺序很要紧**：真实样本「学生工作处审核不通过」同时含「审核」（像进行中）
和「不通过」（是结束）。先判否定词，否则退回会被当成「还在流程里」。

**两条刻意的保守**：

* 「已通过」但读不到教室（`FJ`/`JASMC` 都空）→ 进 `unmatched`，**不发通知**。
  一条没有教室的「已通过」会误导人。
* 认不出的一律进 `unmatched`，**绝不猜**。猜错会把 A 活动的结果安到 B 头上。

## 2. 幂等：插件可以随便重投

插件每次都投**全量**最省心（它不用做 diff）。为此这边三处都幂等：

| 位置 | 做法 |
|---|---|
| 账本 | **只追加**；按 `SQBH` 比 `outcome`，一样就不重复记 |
| `notificationId` | `sha1(sqbh\|outcome\|rooms)[:8]`，**不含时间戳** —— 含了就每轮都变，下游去重立刻失效 |
| QQ 通知 | 写 `pending/` 前先看 `pending/` 与 `done/` 里有没有同 id；有就跳过（否则社员收到两条） |
| 语雀 | `yqa refresh-approval` 自身幂等：内容没变一个字都不写 |

## 3. 为什么不落 PII

服务器是**明文 HTTP**（没有域名与证书）。插件那份记录里有借用人姓名与手机号，
而通知只需要姓名（QQ 映射用）。所以：

* `intake.normalize_record()` 用**白名单**取字段，**手机号（`JYRDH`/`phone`）
  在这一行就被丢弃**，既不落盘也不进通知；
* 契约里也请插件尽量别投手机号（见 `intake-contract.md` §4）—— 网络那一程躲不掉，
  但至少磁盘上没有。

## 4. 为什么写文件给桥，而不是给桥加接口

`yqa` 的 `docs/handoff.md` §3 已经把「通知事件 → `outbox/notify/pending/` → 桥取件 →
发 QQ → 移 `done/`」冻结成契约了。照它写文件就行：**不用改桥的任何代码**，
也不用新开一个鉴权面。新增的两个 `kind`（`borrow_approved` / `borrow_rejected`）
与 agent 的 `accepted` / `rejected` 是两件事，所以没有复用。

## 5. 纪律

程序只做**可测量的事实**：查表、正则、算术、留痕。
不在这里做「判断」—— 判断的落点是「认不出就说认不出，交给人看」。
（上游 `yuque-agent` 的 `docs/principles.md` 是这条纪律的完整来历。）
