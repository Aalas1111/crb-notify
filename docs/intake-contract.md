# 投递契约（给浏览器插件那一侧）

> 这边是**接收方**。你（插件）负责读学校的申请列表，把结果 POST 过来；
> 我们负责判定「哪些审批结束了」并分发通知（QQ + 语雀）。
>
> **你不需要改现有的导出逻辑** —— 直接把你已经产出的那份 `RECORDS JSON`
> 投过来就能用（见 §3）。

## 1. 端点

```
POST http://<服务器地址>:8788/intake/records
```

* 服务器地址单独交接（**不写进仓库**）；
* 这个端口对公网开放，**但请只投数据** —— 没有别的入口，也没有任何指令类接口。

## 2. 怎么发（跨域与鉴权）

油猴脚本的 `@grant none` 意味着你只能用**页面上下文**的 `fetch`，
而页面在 `ehallapp.nju.edu.cn`，目标在另一个域 → **跨域**。所以：

| 事项 | 做法 |
|---|---|
| **推荐**：避免预检 | 用 `Content-Type: text/plain` 发 JSON 字符串 —— 这是「简单请求」，不会先发 `OPTIONS` |
| 或者 | `Content-Type: application/json` 也行，我们会正常应答 `OPTIONS` 预检 |
| **鉴权** | 请求头 `X-Intake-Key: <密钥>`（也可以放 query `?key=`） |
| 响应 | 带 `Access-Control-Allow-Origin`（反射你的 Origin），`response.json()` 可直接读 |

```js
// 最小可用示例（油猴脚本里）
const res = await fetch("http://<服务器地址>:8788/intake/records", {
  method: "POST",
  headers: { "Content-Type": "text/plain", "X-Intake-Key": "<密钥>" },
  body: JSON.stringify({ schemaVersion: "nova.borrow-records.v1", records }),
});
const out = await res.json();   // { ok, received, new, total, ... }
```

> **关于密钥**：它是油猴脚本，**源码谁装上都能看**，所以这串密钥必然是公开的。
> 我们按这个事实设计：这边**只收数据、幂等、无副作用**，密钥只是用来挡误投和扫描器。
> 你按普通常量写就行，不必为它做混淆。

## 3. 载荷

```jsonc
{
  "schemaVersion": "nova.borrow-records.v1",   // 可选，仅用于将来兼容
  "sentAt": "2026-09-27T10:30:00.000Z",        // 可选，便于你排查
  "records": [ /* 见 §4 */ ]                    // 必需
}
```

也接受**顶层直接是数组**（`[ {...}, {...} ]`），以及 `{"data": {"records": [...]}}`。
**最省事的做法**：把你现在那份 `RECORDS JSON` 原样投过来 ——
它已经有 `records` 数组、每项带 `raw`（见下）。

## 4. 每条记录

**优先用 `raw`**：那是学校接口的原样返回，字段名与语义都在，我们按它判定。
`raw` 缺失时才退回扁平字段。所以：

* 如果 `raw` 在（你现在的导出就有）→ **什么都不用改**；
* 如果只想投必要的几个字段 → 参照下表补一个扁平的也行。

| 我们需要 | `raw` 里的字段名 | 扁平字段（`raw` 缺失时） | 说明 |
|---|---|---|---|
| 申请编号 | `SQBH` | `sqbh` | 32 位十六进制；**它是幂等键** |
| 状态码 | `SHZT` | `statusCode` | 如 `99` / `-68` / `65` / `00` |
| 状态描述 | `SHZT_DISPLAY` | `status` | 如「学生工作处审核不通过」 |
| 审核标志 | `SHBZ` | —— | 如「通过」/「不通过」 |
| 审核意见 | `SHYJ` | `feedback` | 退回原因 |
| 分配教室 | `FJ` / `JASMC` | `room` | 通过时才有值 |
| 借用日期 | `KSRQ` | `date` | `YYYY-MM-DD` |
| 节次（起/止） | `KSJC_DISPLAY` / `JSJC_DISPLAY` | `slot` | 形如 `第4节(11:10-12:00)` |
| 校区 | `XXXQDM_DISPLAY` | `campus` | 形如 `仙林校区` |
| 借用人 | `JYRXM` | `borrowerName` | 通知里会用到 |
| 用途/活动名 | `JYYTMS` | `purpose` | 通知标题用它 |
| 申请时间 | `SQRQ` | `requestedAt` | 仅留档 |

### ⚠️ 请不要投手机号

服务器是**明文 HTTP**（没有域名和证书）。`raw` 里的 `JYRDH` 与扁平的 `phone`
**我们收到后会立刻丢弃、不落盘、不进通知** —— 但它在网络上仍会明文过一次。
如果你方便，**投之前就把 `JYRDH` / `phone` 删掉**会更干净；
不方便也没关系，我们这边保证不落盘。

## 5. 什么时候投

* **够用就好**：cac 打开教室借用界面时投一次（你现在的方案就是这样）；
* 我们这边**完全幂等** —— 同一份重复投、或者每次都投全量，都不会产生重复通知
  （按 `SQBH` 与本地账本比对，只有新出现的「审批结束」才会通知）；
* 所以**不需要**你做增量 diff，投全量最省心。

## 6. 响应

```jsonc
{
  "ok": true,
  "received": 12,        // 这次收到几条
  "new": 2,              // 其中「新结束的」几条
  "total": 5,            // 通知文档累计几条
  "unmatched": 1,        // 认不出对应语雀申请的（进 unmatched.json 等人看，不发通知）
  "ended_seen": 6,       // 收到里判定为「已结束」的条数
  "checked": 12,
  "delivery": {          // 两条出路各自的结果
    "qq": { "ok": true, "written": ["..."], "skipped_already_sent": [] },
    "yuque": { "ok": true }
  }
}
```

失败时 `ok: false` + `error`（如 `密钥不对` / `载荷里找不到 records 数组`）。

## 7. 我们收到之后会做什么（便于你对齐预期）

1. **判定**：按 `SHBZ` / `SHZT_DISPLAY` 的关键词判「已通过 / 已退回 / 还在流程 / 草稿」，
   认不出的一律进 `unmatched.json` 等人看 —— **不猜**；
2. **记账**（只追加，按 `SQBH`）+ 生成对外文档；
3. **分发两条路**：
   * **QQ 通知** → 写进 yqa 的 `outbox/notify/pending/`，桥取件发出去
     （`kind` 是 `borrow_approved` / `borrow_rejected`，`member.name` 用借用人姓名）；
   * **语雀《审批结果》** → 让那篇文档重生。

> 「已通过」必须能读到一个教室（`FJ`/`JASMC`）。读不到就不发通知，进 `unmatched` ——
> 一条没有教室的「已通过」会误导人。

## 8. 限制

| 项 | 值 |
|---|---|
| 载荷上限 | 4 MB |
| 单次最多条数 | 2000（你现在是每页 100，够用） |
| 超时 | 我们会同步判定后返回，通常 < 1 秒（若语雀那步慢，最多几秒） |

## 9. 拿假数据试（欢迎，但请看完这两条）

**随便投，这边不校验「这个申请到底存不存在」**：对不上任何语雀申请的记录会进
`unmatched.json` 等人看，**不会产生任何通知**。想验证链路通不通，看响应里的
`ok` / `received` 就够了。

1. **想看到「真的出一条通知」**，这条记录得能对上语雀那边的活动。比对三个字段：
   `KSRQ`（日期）+ `KSJC_DISPLAY` / `JSJC_DISPLAY`（节次，要含「第N节」）+
   `JYYTMS`（用途，比较时会忽略括号里的内容）。当前 `plan.json` 里是这两条：

   | 日期 | 节次 | 用途 |
   |---|---|---|
   | `2026-09-30` | 第3节 ~ 第4节 | `大肥鱼deepseek` |
   | `2026-09-30` | 第10节 ~ 第12节 | `cac` |

   ⚠️ 但对上之后**会真的发 QQ 通知**（桥会把 `pending/` 里那条发到群里），
   所以拿真活动试之前先跟负责人打个招呼。
2. **假记录会留在账本里**（账本只追加，`unmatched.json` 是从它重生的），
   事后想清掉得找我们手改 —— 试的时候用明显假的 `SQBH` 便于认。

另外：判成「已通过」**必须带教室**（`FJ` / `JASMC`），否则同样进 `unmatched`
（一条没有教室的「已通过」会误导人，我们不发）。判成「草稿 / 还在流程」的记录
**连账本都不进**，投多少次都不会有动静。
